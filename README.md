# Telegram-бот для ассесмента «ИИ в научных исследованиях»

Бот проводит ассесмент прямо в чате (15 утверждений «Согласен/Не согласен» с обоснованием,
15 закрытых вопросов, эссе 500–700 слов), автоматически проверяет ответы и сохраняет
результат каждого слушателя в Google Sheets.

## Как это оценивается

- **Часть 1** (макс. 30 баллов): правильность выбора проверяется по ключу автоматически;
  качество обоснования оценивает LLM (Perplexity `sonar`) по ключевым аргументам из
  материалов курса. 2 балла — верный выбор + верное по сути обоснование, 1 — верный выбор без
  обоснования или с ошибкой в нём, 0 — неверный выбор.
- **Часть 2** (макс. 15 баллов): полностью автоматически по ключу; в вопросах с несколькими
  верными вариантами балл начисляется только за полный и точный набор.
- **Часть 3** (макс. 20 баллов): эссе оценивает LLM по промпту из ваших материалов
  (4 критерия × 5 баллов).
- Итог 0–65 баллов переводится в оценку по шкале: 56–65 «Отлично», 45–55 «Хорошо»,
  34–44 «Удовлетворительно», <34 «Неудовлетворительно».

Все сырые ответы, обоснования, текст эссе и комментарии LLM сохраняются в Google Sheets
(колонки `*_details_json`) — так преподаватель может при желании перепроверить оценку вручную.

## Установка

```bash
cd /Users/afomin/telegram-assessment-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка

### 1. Telegram-токен

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram → `/newbot`.
2. Скопируйте выданный токен в `.env` → `TELEGRAM_BOT_TOKEN`.

### 2. Perplexity API

Ключ `PERPLEXITY_API_KEY` уже прописан в `.env`. При желании смените модель через
`PERPLEXITY_MODEL` (по умолчанию `sonar`).

⚠️ Ключ был передан в открытом чате — если это чувствительно для вас, стоит перевыпустить
его в личном кабинете Perplexity после настройки.

### 3. Google Sheets

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект → включите
   **Google Sheets API** и **Google Drive API**.
2. Создайте сервис-аккаунт (IAM & Admin → Service Accounts), затем ключ типа JSON —
   скачается файл вида `xxx.json`. Сохраните его в папку проекта как `credentials.json`
   (или укажите свой путь в `.env` → `GOOGLE_SERVICE_ACCOUNT_JSON`).
3. Создайте пустую Google Таблицу, скопируйте её ID из URL
   (`https://docs.google.com/spreadsheets/d/<ЭТОТ_ID>/edit`) в `.env` → `GOOGLE_SHEET_ID`.
4. Откройте доступ к таблице для email сервис-аккаунта (поле `client_email` в JSON-файле) —
   «Редактор».
5. Бот сам создаст лист `Results` (или имя из `GOOGLE_SHEET_NAME`) и заголовки при первом
   сохранении.

## Запуск

```bash
python bot.py
```

Бот работает через long polling — процесс должен быть постоянно запущен (например, в
`tmux`/`screen`, как systemd-сервис, или в облаке).

## Сценарий для слушателя

1. `/start` → бот показывает инструкцию, просит ФИО.
2. Часть 1: 15 утверждений, кнопки «Согласен/Не согласен» → затем текстовое обоснование.
3. Часть 2: 15 вопросов; для вопросов с несколькими верными вариантами — отметить чекбоксы
   и нажать «Готово».
4. Часть 3: эссе можно отправить несколькими сообщениями, завершить командой `/done`.
5. Бот показывает итоговые баллы и оценку, сохраняет всё в Google Sheets.
6. `/cancel` — прервать прохождение в любой момент (прогресс не сохраняется).

## Веб-версия (без Telegram)

Тот же ассесмент доступен как обычная веб-страница (`webapp.py`, Flask) — использует те же
`questions.py`/`scoring.py`/`sheets.py`, пишет результаты в ту же таблицу с пометкой
`source = web`.

Локально:

```bash
source .venv/bin/activate
python webapp.py   # http://localhost:5050
```

### Постоянный бесплатный деплой на Render.com

1. Создайте (если ещё нет) аккаунт на [github.com](https://github.com) и [render.com](https://render.com)
   — это нужно сделать самостоятельно, через браузер.
2. Создайте пустой репозиторий на GitHub, затем из папки проекта:
   ```bash
   git remote add origin <URL_вашего_репозитория>
   git branch -M main
   git push -u origin main
   ```
   (`.env` и `credentials.json` не попадут в репозиторий — они в `.gitignore`.)
3. В Render: **New → Web Service** → подключите этот GitHub-репозиторий.
   - Runtime: Python 3
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `gunicorn webapp:app --workers 2 --threads 4 --timeout 120 --bind 0.0.0.0:$PORT`
     (уже описано в `Procfile`, Render может подхватить его автоматически)
4. В разделе **Environment** добавьте переменные:
   - `PERPLEXITY_API_KEY`
   - `PERPLEXITY_MODEL` = `sonar`
   - `GOOGLE_SHEET_ID`
   - `GOOGLE_SHEET_NAME` = `Results`
   - `GOOGLE_SERVICE_ACCOUNT_JSON_CONTENT` = вставить **всё содержимое** JSON-файла
     сервис-аккаунта одной строкой (это самый простой способ передать секрет без файла
     — код уже поддерживает такой вариант).
5. Deploy. Render выдаст постоянный URL вида `https://<имя-сервиса>.onrender.com`.

Бесплатный план Render "засыпает" после ~15 минут без запросов и просыпается ~30–60 секунд
на первый запрос — для учебного ассесмента это некритично.

## Ограничения

- Каждый пользователь Telegram проходит ассесмент по одному разу за сессию бота (повторный
  `/start` перезапускает и обнуляет текущий незавершённый прогресс в памяти процесса, но не
  удаляет уже сохранённые в Sheets строки).
- Оценка обоснований/эссе через LLM — не эталонная человеческая проверка; при сбое API бот
  сохраняет результат с пометкой о необходимости ручной проверки.
